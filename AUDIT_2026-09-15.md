# Pipeline Audit — 2026-09-15

Scope: the `newscrawler/` crawl pipeline (sitemap → article → filter → chunk → embed → save) and its operational tooling. Every finding below was verified either against the live sites (`scripts/check_crawlers.py`, a UA probe) or reproduced with a mocked-network script. Nothing here is inferred from reading code alone.

Each finding is written so it can be pasted into a ticket as-is: **ID · Severity · Where · Symptom · Root cause · Evidence · Fix · Done when**.

Severity scale: **P0** silent data loss / production currently produces nothing · **P1** systemic bug affecting many sources · **P2** single-source breakage · **P3** hygiene / tech debt.

## SYS — Pipeline bugs that make breakage silent

### SYS-01 · P0 · Extraction fallback is skipped when the site extractor returns `[]`

- **Where:** `newscrawler/infrastructure/datasource/scrapers/crawler.py:198` and `:220`
- **Symptom:** When a site's article layout changes, the article is saved with empty text instead of falling back to trafilatura / newspaper3k. Today this is exactly why KUMPARAN is PARTIAL.
- **Root cause:** The fallback condition is `extracted_text is None or extracted_text == ""`. Every one of the 32 crawlers' `_get_whole_text` returns `None` when the container `<div>` is missing, but returns an **empty list `[]`** when the container exists and no `<p>` matched (or all paragraphs were boilerplate-filtered). `[]` is neither `None` nor `""`, so both fallbacks are bypassed.
- **Evidence (mocked repro):**
  ```
  selector miss -> None            -> fallback_used=True
  container found, no <p> -> []    -> extracted_text=[]  fallback_used=False
  ```
- **Downstream effect:** the empty `NewsDetailsDTO` passes through `mark_sitemaps_attempted`, may pass the semantic filter on title alone, produces zero chunks, and is never saved as an article. The sitemap is stamped attempted and retried in 7 days with the same result.
- **Fix:** Change both conditions to `if not extracted_text:`. Additionally add a minimum-content sanity check (e.g. total chars < 200 → treat as failed and try the next extractor).
- **Done when:** a unit test with a crawler whose `_get_whole_text` returns `[]` shows trafilatura output in `extracted_text`; KUMPARAN moves from PARTIAL to OK/FALLBACK in `check_crawlers.py`.

### SYS-02 · P0 · A crash in `_get_reporter_from_text` / `_get_whole_text` drops the article and retries it forever

- **Where:** `crawler.py:194` (reporter extraction runs first, no try/except around either call); OKEZONE example at `scrapers/okezone/okezone_crawler.py:72`
- **Symptom:** OKEZONE is PARTIAL with `'NoneType' object has no attribute 'find'` logged per article. Those articles are re-fetched on **every run**.
- **Root cause:** Site-specific extractors do things like `soup.find(...).find(...)` with no None-guard. Any exception propagates to the outer `except BaseException` in `_get_news_details`, which returns `None`. A `None` result (a) never reaches the fallbacks and (b) is not in `newsdetails`, so `mark_sitemaps_attempted` is never called for it → it stays at the top of the "no article" queue and burns one of the 1,000 fetches per run, every run.
- **Fix:** Wrap `_get_reporter_from_text` and `_get_whole_text` individually in try/except inside `_get_news_details`; treat an exception as "extractor failed" so the fallback chain still runs. Consider also stamping `last_crawl_attempt` for hard failures with a shorter cooldown (e.g. 1 day) so a permanently broken extractor cannot monopolise the queue.
- **Done when:** a crawler whose `_get_whole_text` raises still yields a trafilatura-extracted DTO; OKEZONE moves off PARTIAL.

### SYS-03 · P0 · `SQLAlchemyClient.get_session` swallows every exception

- **Where:** `newscrawler/infrastructure/network/clients/sqlalchemy_client.py:38`
- **Symptom:** A DB outage during a scheduled crawl produces a `crawl_log` row with `status='completed'` and 0 sitemaps/articles — never a failure. Reproduced live on 2026-09-15 with Postgres stopped: a read script printed a header and continued as if its queries had succeeded.
- **Root cause:** The `@contextmanager` catches `Exception`, logs, rolls back, and **does not re-raise**. The `with` block exits normally, so `save_sitemaps` returns its pre-initialised `[]`, `load_all_sitemaps` returns `[]` ("Found 0 news to crawl"), `mark_sitemaps_attempted` silently no-ops, etc.
- **Fix:** Re-raise after rollback (`raise`). Audit callers that currently depend on the swallow (integration tests included).
- **Done when:** with Postgres stopped, `process_event` results in a logged failure and a non-zero exit (see SYS-06), not `completed`.

### SYS-04 · P1 · `crawl_log.article_count` is always 0 for `full_text`

- **Where:** `newscrawler/domain/services/crawler_service_impl.py:60-63`
- **Symptom:** The "red flag: `article_count=0` for a source that normally produces articles" query in `OPERATIONS.md` cannot distinguish a broken source from a healthy one.
- **Root cause:** `total_saved = 0` is declared and passed to `log_crawl_complete` but never incremented; `_crawl_newsdetails_inner` doesn't return a count.
- **Fix:** Have `_crawl_newsdetails_inner` return `(attempted, extracted, passed_filter, saved)` and log all four. The extracted/attempted ratio per source is the single most useful "is this scraper rotting" metric.
- **Done when:** `SELECT website, article_count FROM crawl_log WHERE task='full_text'` shows non-zero values for healthy sources.

### SYS-05 · P1 · Page-loader retry only catches `ReadTimeout`; `ConnectionError` is never retried

- **Where:** `newscrawler/core/page_loader/requests_page_loader.py:34` (and the inner `except` on line ~44)
- **Root cause:** `except requests.exceptions.ReadTimeout or requests.exceptions.ConnectionError:` — Python evaluates `A or B` on two classes to `A`. Only `ReadTimeout` is caught; `ConnectionError` (connection reset, DNS, TLS) falls through to the generic `except BaseException` → 1 attempt, returns `None`.
- **Evidence (mocked repro):** `ConnectionError: max_retries=5, actual attempts=1` · `ReadTimeout: max_retries=5, actual attempts=6`.
- **Fix:** `except (requests.exceptions.ReadTimeout, requests.exceptions.ConnectionError):` in both places. While there: use a `requests.Session` with `HTTPAdapter(max_retries=Retry(total=3, backoff_factor=1, status_forcelist=[429, 500, 502, 503, 504]))` and delete the hand-rolled loop.
- **Done when:** unit test with a patched `requests.get` raising `ConnectionError` shows `max_retries + 1` attempts.

### SYS-06 · P1 · `process_event` catches `BaseException`, logs at INFO, exits 0

- **Where:** `newscrawler/application/api/lambda_function/lambda_handler.py:39`
- **Symptom:** Task Scheduler / cron always sees success. Combined with SYS-03 there is no path by which a failed run becomes visible without opening the DB.
- **Fix:** Log at `ERROR` with traceback (`logger.exception`), re-raise (or `sys.exit(1)` in `__main__.py`). Consider a per-run summary line (`sources=N ok=N failed=[...] articles=N`) on stdout for the scheduler log.
- **Done when:** a forced failure in `crawl_sitemaps` makes `python __main__.py` exit non-zero.

### SYS-07 · P1 · Sitemap date gate drops never-seen articles before dedup

- **Where:** `newscrawler/infrastructure/datasource/dataflow/write/news_data_source.py:45`
- **Symptom:** If a scheduled run is missed (or a source was broken for a while), the articles published in that window can never be picked up from the sitemap, even though they're still listed.
- **Root cause:** `save_sitemap` keeps an entry only if `posted_at - max_posted_at_for(source, category)` has `days >= 0 and seconds > 0`. This runs **before** the real `(link, posted_at)` dedup in `save_sitemaps`, so any never-seen entry that is older than the stored max date — or posted at exactly 00:00 on that date — is discarded. The tz handling (`+07:00` replaced with `+00:00`) makes the boundary off by 7 hours as well.
- **Evidence (mocked repro, last max = 2026-09-01):** `posted 2026-09-15 KEPT · posted 2026-08-30 DROPPED · posted 2026-09-01 00:00 DROPPED · posted 2026-09-01 09:00 KEPT`.
- **Fix:** Delete the gate; `save_sitemaps` already dedups on `(link, posted_at)` with a pre-fetched map. If the gate exists for performance, replace it with a bounded window (e.g. skip entries older than 30 days) rather than "older than max".
- **Done when:** `scripts/backfill_missing_articles.py`-style re-run of a sitemap after a gap inserts the missed rows.

## OPS — Observability & tooling gaps

### OPS-01 · P1 · `check_crawlers.py` is not scheduled

- **Where:** `OPERATIONS.md` schedule table; no Task Scheduler / cron entry references the script.
- **Symptom:** Breakage is discovered by a human noticing missing articles, sometimes weeks later (13/32 healthy on 2026-06-02; 18/32 today, with different outlets broken).
- **Fix:** Add a daily 05:30 WIB job running `venv\Scripts\python.exe scripts/check_crawlers.py --quiet --log-db`; on exit code 1 send a notification (Telegram bot, email, or even a Windows toast). Keep the JSON reports in `crawler_health/` for trend queries.
- **Done when:** a broken source is reported within 24 h without anyone running a command.

### OPS-02 · P1 · Health check reports "OK" when the site extractor is dead and trafilatura rescued it

- **Where:** `scripts/check_crawlers.py` (`classify`, `check_one`); `crawler.py` logs "Standard extraction failed … Trafilatura fallback" but nothing records it.
- **Symptom:** CNBC, CNN, KONTAN, PIKIRANRAKYAT are all "OK" today; every sampled article hit the fallback. When trafilatura also fails on those sites, they will flip straight to PARTIAL with no warning.
- **Fix:** (1) Return which extractor produced the text from `_get_news_details` (e.g. `meta_data["extractor"] = "site" | "trafilatura" | "newspaper"`) and persist it on `articles`; (2) add a `FALLBACK` status to `check_crawlers.py` when `detail_ok > 0` but no sample used the site extractor; (3) treat FALLBACK as "needs attention" but non-fatal.
- **Done when:** the four sources above show FALLBACK; `SELECT meta_data->>'extractor', count(*) FROM articles GROUP BY 1` works.

### OPS-03 · P2 · Health check only samples the first branch

- **Where:** `scripts/check_crawlers.py:94` (`first_name, first_link = next(iter(branches.items()))`)
- **Symptom:** The sampled branch is "Bobo" for GRIDID, "AksaraJabar" for PIKIRANRAKYAT, "suara-pembaca" for DETIK, "www" for TEMPO — often not the finance section the pipeline cares about, and a different HTML template than the news pages.
- **Fix:** Prefer a branch matching `ekonomi|bisnis|market|finance|keuangan|money|uang` when present; otherwise sample 2 branches.
- **Done when:** the report's `branch` column shows a finance section for sources that have one.

## SRC — Per-source breakage (live, 2026-09-15)

UA probe: every sitemap URL was fetched with the project's 2017 `Chrome/56` User-Agent and with a modern `Chrome/128` UA. **Results were identical**, so bot-blocking by UA is not the cause for any outlet.

### SRC-01 · P0 · EMITENNEWS always crashes — and is the only source enabled in `__main__.py`

- **Where:** `scrapers/emitennews/emitennews_crawler.py:40` (`_scrape`), `_get_link` override, `_get_timestamp` at `:83`; `__main__.py` `SLOW` list.
- **Symptom:** `TypeError: argument of type 'NoneType' is not iterable` on every run. Net effect: the currently scheduled crawl produces nothing.
- **Root cause:** `_scrape` iterates `sitemap_child_soup.find_all("loc")` and passes each `<loc>` tag to `_get_link`, which does `news_soup.find("loc")` — a `<loc>` has no child `<loc>` → `None` → `"/news/" not in None` raises. Separately, `_get_timestamp` returns `now()` for every entry, so the `(link, posted_at)` dedup key changes daily and the same article is re-inserted on every run.
- **Fix:** Iterate `find_all("url")` (the parent) and let `_get_link` find `loc` inside it; parse `<lastmod>` for the timestamp instead of `now()`. Re-enable the other sources in `__main__.py` (or drive the list from an env var).
- **Done when:** `check_crawlers.py --website EMITENNEWS` is OK; two consecutive runs do not create duplicate `sitemaps` rows.

### SRC-02 · P2 · Dead or wrong sitemap URLs (HTTP 404)

- **Where:** `newscrawler/domain/entities/extraction/url_data.py`
- **Outlets:**
  - **ANTARANEWS** (`:15`) — `https://en.antaranews.com/rss/spo.xml` is an *English-language sports RSS feed*, not an Indonesian news sitemap. 404 today.
  - **BATAMPOS** — `https://batampos.co.id/news-sitemap.xml` 404
  - **KAPANLAGI** — `https://www.kapanlagi.com/sitemap.xml` 404
  - **TIRTO** — `https://tirto.id/s/sitemap-content.xml` 404
  - **SUARA** (`:27`) — `URL.SUARA = ""`; crawler fetches an empty URL.
- **Fix:** Locate each site's current news sitemap (check `/robots.txt` `Sitemap:` lines first), update the enum, re-verify `_get_branches` against the new index format. If a site no longer publishes a sitemap, remove it from `CRAWLER_DICT` rather than leaving it to fail every run.
- **Done when:** each outlet is OK or explicitly retired.

### SRC-03 · P2 · Blocked at the sitemap level regardless of User-Agent (HTTP 403)

- **Outlets:** **BISNIS** (`sitemap-news.xml`, 403 with 5 KB HTML challenge page), **IDNTIMES** (403, empty body).
- **Note:** BISNIS was OK on 2026-06-02, so this is new server-side protection. BISNIS has the highest `SOURCE_AUTHORITY` weight (1.0) in `constants.py`, so its absence affects newsletter ranking.
- **Fix options, in order of cost:** try an RSS endpoint or a different sitemap path; add realistic headers (`Referer`, `Accept-Language: id-ID`, `Sec-Fetch-*`); fall back to a headless loader (`core/page_loader/headless_page_loader.py` exists but is unused; `EXECUTABLE_PATH` default points at a macOS path).
- **Done when:** listing returns > 0 links via `check_crawlers.py`.

### SRC-04 · P2 · INEWS — TLS certificate verification fails

- **Symptom:** `SSLError(CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate)` for `https://www.inews.id/sitemap.xml`.
- **Fix:** Check whether the site's chain is incomplete (test with `openssl s_client`); if so, either add the intermediate to a custom CA bundle passed via `verify=` or, as a last resort, `verify=False` for this host only. Update `certifi` in the venv first (`requirements.txt` pins `certifi==2022.12.7`).
- **Done when:** sitemap fetch returns 200.

### SRC-05 · P2 · Sitemap index format changed — `_get_branches` finds nothing

- **LIPUTAN6** — `scrapers/liputan_enam/liputan_enam_crawler.py:34` filters on `"sitemap_news" in link`; the live index now lists `https://www.liputan6.com/<section>/sitemap.xml` (28 entries: news, bisnis, showbiz, bola, …). Result: "no branches parsed from sitemap".
- **Fix:** match `/<section>/sitemap.xml` and extract `<section>` as the branch name; prefer `bisnis`.
- **Done when:** LIPUTAN6 OK.

### SRC-06 · P2 · Branch sitemap format changed — `_scrape` finds 0 `<url>`

- **MERDEKA** — index lists `https://www.merdeka.com/<section>/sitemap.xml` (13 entries, incl. `uang`); the first branch parsed to 0 links.
- **TEMPO** — index lists `https://www.tempo.co/<section>-sitemap.xml` (28 entries, incl. `ekonomi-sitemap.xml`); branch "www" parsed to 0 links.
- **Root cause (likely):** the branch files are now nested sitemap indexes or use a different tag set; needs a fetch-and-look. Also note `_get_branches` in both picks a non-finance branch first.
- **Fix:** inspect the branch XML, update `_scrape` / `_get_branches`; target `uang` (MERDEKA) and `ekonomi` (TEMPO) explicitly.
- **Done when:** both OK.

### SRC-07 · P2 · Article layout changed (the genuine "layout" cases)

- **KUMPARAN** — `scrapers/kumparan/kumparan_crawler.py:42` looks for `span[data-qa-id="story-paragraph"]`; not present anymore → `[]` → fallback skipped (SYS-01). Listing works (100 links).
- **OKEZONE** — `scrapers/okezone/okezone_crawler.py:72` looks for `div.detail.detail__billboard.class-vidy`; not present → `AttributeError` (SYS-02). Also its first branch serves articles from 2025-08, i.e. a stale sitemap; check `_get_branches`.
- **Fix:** Fixing SYS-01/SYS-02 makes both work via trafilatura immediately. Then update the selectors (or delete them and rely on the fallback if trafilatura quality is fine — see DBT-05).
- **Done when:** both OK (not FALLBACK) or explicitly fallback-only.

### SRC-08 · P2 · Site extractor dead, masked by trafilatura ("OK" but degraded)

- **Outlets:** **CNBC**, **CNN**, **KONTAN**, **PIKIRANRAKYAT** — every sampled article logged `Standard extraction failed … Attempting Trafilatura fallback … successful`.
- **Risk:** reporter/author extraction is also site-specific and is silently empty for these; boilerplate filtering ("Baca juga", ads) is bypassed; and if trafilatura ever fails they go straight to PARTIAL.
- **Fix:** After OPS-02 lands, either refresh the selectors or consciously mark these as trafilatura-first.
- **Done when:** each shows OK (site extractor) in the health report, or FALLBACK by decision.

## DBT — Hygiene / tech debt

### DBT-01 · P3 · `requirements.txt` is stale; pydantic 1.7 pinned, 2.11 installed

- **Where:** `requirements.txt:19` (`pydantic==1.7.3`); venv has 2.11. Also missing: langchain, faiss, sentence-transformers (wrong version), google-genai, fastapi, uvicorn, trafilatura (wrong version), newspaper3k, scikit-learn, python-dotenv.
- **Effect:** `SitemapDTO.timestamp: datetime = None` (`site_map_dto.py:12`) relied on pydantic-v1's implicit `Optional`; under v2 `None` is rejected, so any `<url>` entry without `<news:publication_date>` is silently dropped in `_get_sitemap`'s `except BaseException`. Behaviour is accidental, not designed.
- **Fix:** `pip freeze > requirements.txt` from the venv (or move to `pyproject.toml`); make the annotation `Optional[datetime]` and decide explicitly what to do with undated entries (use `<lastmod>`, or drop with a WARNING count).

### DBT-02 · P3 · The MiniLM model is loaded twice per process

- **Where:** `crawler_service_impl.py:35` (`SemanticImportanceFilter`) and `chunk_faiss_data_source.py:18` (`HuggingFaceEmbeddings`) both load `paraphrase-multilingual-MiniLM-L12-v2`.
- **Fix:** share one `SentenceTransformer` instance (inject it into both).

### DBT-03 · P3 · `NewsDataSource` builds a second `SQLAlchemyClient` instead of using the injected one

- **Where:** `news_data_source.py:32` — `SQLAlchemyArticleDataSource(SQLAlchemyClient())`.
- **Effect:** two engines/pools per process; `sent_to_local`/isolation-level arguments passed to the outer client are ignored for article writes.
- **Fix:** pass `sql_alchemy_client` through.

### DBT-04 · P3 · Branch selection is not filtered, so the 1,000/run queue fills with non-finance articles

- **Where:** each crawler's `_get_branches`; `crawler_service_impl.py` (`limit=1000`, queue ordered by `posted_at DESC` across all categories).
- **Effect:** showbiz/sports/kids sections (Bobo, showbiz, olahraga…) are fetched, then discarded by the semantic filter. On a busy day a source can exceed 1,000 non-finance URLs and starve the finance ones. Wasted bandwidth and time; unnecessary load on the target sites.
- **Fix:** add an optional per-source allow-list of branch names (ekonomi/bisnis/market/uang/finance/keuangan); apply it in `get_news_in_bulk`.

### DBT-05 · P3 · Extraction strategy is selector-first, which is the brittle order

- **Where:** `crawler.py:_get_news_details`.
- **Observation:** site-specific CSS selectors are the thing that rots; trafilatura and JSON-LD (`<script type="application/ld+json">` → `NewsArticle.articleBody`, which most Indonesian portals publish) are layout-independent. Today the layout-independent methods are only reached after the brittle one fails.
- **Proposal:** (1) extract `articleBody` from JSON-LD when present; (2) else trafilatura; (3) site selector only as an override for outlets where 1–2 produce poor text. Keep `_get_reporter_from_text` but also read `author` from JSON-LD. Record the extractor used (OPS-02). This reduces the per-site surface area to `_get_branches` + sitemap parsing, which is what actually needs to be site-specific.
- **Done when:** number of outlets requiring a custom `_get_whole_text` drops materially and `check_crawlers.py` FALLBACK count is zero by design.

## Appendix C — How the findings were verified

- Live: `venv\Scripts\python.exe scripts/check_crawlers.py --sample-size 2` (full log retained), plus a UA probe script hitting every `URL` enum value with both header sets.
- Mocked repros (no network, no DB) for SYS-01, SYS-02, SYS-05, SYS-07: a `Crawler` subclass with a stubbed `page_loader.get_soup` and patched `newspaper.Article`; `requests.get` patched to raise; `NewsDataSource` with a `MagicMock` sitemap datasource.
- SYS-03 observed directly: with Postgres stopped, a query script continued past a swallowed `OperationalError`.
- Production `crawl_log` / per-source gap counts could **not** be checked because Postgres was not running at audit time — worth doing as the first step of SYS-04.
