# ADR-029: Arm B retry -- faithful near-copies in training and in the exam, with pass criteria fixed in advance

**Status:** Accepted (owner, 2026-11-05: "let's retry once")
**Date:** 2026-11-05
**Feature:** nli-faithfulness (SYS-199 #429)
**Author:** 10x-Team (Architect + QA)
**Builds on:** ADR-028 (venv, data isolation, trainer). Changes only the data and the measurement.

## Context
Arm B (2026-11-04) is perfect on the targeted pairs and flags 96-100% of exact copies: every near-copy in its
training pairs was a one-edit corruption, and `to_pairs` drops verbatim copies, so it learned "near-identical =
unfaithful". The exam has the same hole, so the held-out table could not see it; only the identity control did.
The owner allows one retry. If it fails, SYS-199 stops at arm A plus the hedge lexicon gate.

## Decision
1. **New faithful kind `near_copy`:** the premise with ONE meaning-preserving change and every other word kept:
   one word to an exact synonym, an attribution phrase (kata/ujar/menurut X) moved or dropped, or a reorder inside
   one clause. It must not add, drop or change any fact, hedge, denial, date, cause or number. Generated by
   `gen_nli_pairs.py --near-copies N --seeds-from <pairs.jsonl>` for seeds that already exist (no new seeds, so the
   exam and training article sets do not change).
2. **Exam:** 2 near-copies per exam seed in a SEPARATE file `tests/fixtures/nli_eval/near_copies.jsonl`;
   `pairs.jsonl` (SYS-197's deliverable, in QA) is unchanged. Validity like ADR-027's label_ok: Claude labels a
   stratified 40 (8 per type), Gemini labels the same 40 blind; agreement >= 36/40, and the share both call valid
   >= 87%. Below that the near-copy column is not trusted and the retry is judged on identity alone.
3. **Training:** 1 near-copy per training seed (`data/nli_train/near_copies.jsonl`) plus 1 identity pair per seed
   (built in the trainer, free). Same trainer, same hyperparameters, same dev-split rule.
4. **Pass criteria (fixed now, before any number is seen),** per type, at the type's held-out median tau, from
   `compare_nli_arms.py`:
   - held-out recall >= 0.89 (the protocol's floor, as arm A);
   - false flags on restatements and on hard positives <= 0.05;
   - false flags on identity pairs <= 0.05, and on the exam's near-copies <= 0.10.
   A type passes for arm B only if all four hold. Hedge is the type that matters; on the other four arm B must not
   be worse than arm A. Passing still only qualifies a type for SYS-200's natural-set check (ADR-024).
5. **Spend:** cap $1 (estimate about $0.30: 6,500 short calls).

## Alternatives Considered
| Alternative | Pros | Cons | Why Not |
|---|---|---|---|
| Identity pairs only (no spend) | Free, valid by construction | Teaches "exactly equal = faithful, any change = unfaithful"; a synonym swap would still be flagged | Too narrow a fix |
| Add near-copies to `pairs.jsonl` | One exam file | Changes SYS-197's fixture while it is in QA; reopens its checks | Separate file is cleaner |
| Stop at arm A | No spend | Hedge stays on the lexicon gate only | Owner chose one retry |

## Consequences
### Positive
- The exam can now see the near-copy failure for every future arm.
- Pass criteria are written before the run, so the retry cannot be tuned to pass.
### Negative
- LLM-written near-copies can change meaning; the 40-row check bounds that, it does not remove it.
- About 2/3 of our training pairs become faithful; the binary loss is not reweighted (watched in dev pairs accuracy).
### Risks
- B passes the exam and fails on real sentences: SYS-200 still decides promotion.

## Dependencies
- ADR-028 setup; Gemini free tier for the blind 40 (4 calls).
