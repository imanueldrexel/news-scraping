## Hard rules that apply to this batch

All of `HANDOFF_2026-09-20.md`'s hard rules still apply unchanged. The ones this batch will actually hit:

- **A ticket is closed only when its Done-when is met as written**, with the evidence on the ticket. If it cannot be met as written, say so on the ticket and stop — do not redefine it. (The SYS-37 closure did this correctly for the CNBC bucket, and stated the caveat. SRC-35's closure did not, which is how SRC-43 went unnoticed.)
- **Issue first**, even for a one-liner; findings get their own ticket, never a comment on an umbrella ticket. Every probe, benchmark or comparison gets an `EXPERIMENTS.md` entry the same session.
- **Every DB write to existing rows** is `--dry-run` with counts on the ticket, then a backup, then **ask the owner**. SYS-49's disposition of the 124 saved op-eds and anything SYS-48 deletes are both in this class.
- `venv\Scripts\python.exe` for everything; work in the main repo root, never under `.claude/worktrees/`.
- A schema change is the `.sql` file **plus** `migrate.py`'s `MIGRATIONS` **plus** the CLAUDE.md list **plus** the ORM in `table.py`. The reflection test added by DBT-11 now fails on drift — which is the point.

## Traps from this audit (all three are now in `EXPERIMENTS.md`)

- **A fix at the one enforcement point is only as good as its input.** SRC-35 is correctly placed and correctly word-bounded, and still does nothing for a third of the fleet because three subclasses hand it a URL instead of a name. Check what feeds a choke point, not just the choke point.
- **Verify a fleet claim with the shipped function, not the probe script.** `scripts/experiments/probe_branch_scope.py` uses a private regex; `Crawler.is_soft_branch` is what ships. They are different predicates and they disagree. (SRC-43's fix item 4 makes the probe use the shipped helper and adds a fleet assertion against URL keys.)
- **A sidecar that reports its own metrics is not a test of them**, and `gate_metrics(rows, probs, …)` reads P(soft) from a column whose meaning depends on which matrix you passed. Both are DBT-35.
- **Pick the verification bucket for the property you need.** SYS-37's live run on CNBC `news` came back 96.5% news — strong evidence for precision, almost none for recall. The read-only dry-run shape (real `batch_crawling_details` + real `classify_batch`, nothing written) costs ~45 fetches and is how the SINDONEWS `scope` problem surfaced; use it on a bucket the last verification did *not* cover.
