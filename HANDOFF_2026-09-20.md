---

You are the developer on NewsAggregator (`newscrawler/`). On 2026-09-20 the product owner changed the product's scope from **finance/economy only** to **news-worthy** (hard news of any desk in; recipes, prayers, horoscopes, gossip, listicles, fiction and **sports** out; politics and economic policy in), and decided that the article filter becomes a **supervised classifier on the embedding the pipeline already computes**, trained on a Gemini-labelled gold set — the LLM labels and audits, it never gates at runtime. ## Hard rules (these are not preferences)

- **No `task=full_text` or `task=all` on any widened or never-crawled source until SYS-37 is merged.** `rejected_filter` is a permanent terminal state (SYS-16); with the current finance-only filter, every general-news URL you fetch is lost. `task=sitemap` only. The one exception is the finance-narrowed sources as they are *today* (the eight that ran in September).
- **Do not run `task=sitemap` or `task=all` for VIVA until SRC-33 lands** (53 branches × 1,000 URLs onto a 39k backlog).
- **Never narrow a crawler to a finance leaf. Never key a branch by its URL** — a `<loc>` the subclass cannot name is skipped (`re.match` + skip, not `re.sub`). Decide every leaf from a 3-title sample and put the table on the ticket; a leaf's name is not evidence (`transportasi` contains `sport`; WARTAEKONOMI `otomotif` is business coverage).
- **Do not re-tune `INTERESTS`, the 0.35 threshold, `OFFTOPIC_INTERESTS` or the margin.** Three passes on that signal each failed the next audit. SYS-37 replaces it.
- **No LLM call in the per-article crawl path.** Gemini is used offline (SYS-36 labelling, OPS-18 weekly audit) through the existing `google.genai` client and `api_usage_log`. No second provider unless SYS-39's bake-off picks one.
- **Every DB write that touches existing rows** (re-queues, cleanups, category rewrites, migrations) is `--dry-run` with counts on the ticket, then a backup, then **ask the owner** before the real run. Never point `POSTGRES_DB_*` at production from a test.
- **Issue first, always.** A new bug or requirement you discover gets its own ticket (next free `[AREA-NN]`, body per the template, ID map in `CLAUDE.md` updated) before any code — even a one-liner. Findings go in tickets, never as comments on umbrella tickets. Commits end with `Fixes #N` / `Refs #N`. Log every probe, benchmark and comparison in `EXPERIMENTS.md` the same session; reusable probes go in `scripts/experiments/`.
- `venv\Scripts\python.exe` for everything. `tests/unit` must stay offline and green (`-m pytest tests/unit -q`); `tests/integration` needs the `newsaggregator_test` DB on port 5431. A schema change is a `scripts/migrate_*.sql` file **plus** `scripts/migrate.py`'s `MIGRATIONS` **plus** the `CLAUDE.md` list **plus** the ORM model in `table.py` — all four, or the next run dies with `DatatypeMismatch`.
- Work in the main repo root, never under `.claude/worktrees/`.
- A ticket is closed only when its **Done-when** is met as written and the evidence (health line, SQL result, metrics table, `EXPERIMENTS.md` link) is on the ticket. If a Done-when cannot be met as written, say so on the ticket and stop — do not redefine it.

## Traps that have already cost days (do not rediscover)

- `re.sub` on a non-matching link returns the input unchanged — three sources have URL-shaped categories from this (IDNTIMES, VIVA, CNN).
- A substring deny on `sport` matches `transportasi`; a deny-list built from today's category vocabulary has zero coverage of the next source's (`life` ≠ `lifestyle`, `hype`, `korea`, `fiction`).
- A fallback that exists in the code is not a fallback that runs — check whether the condition guarding it can ever be true on the live path (SYS-32/SYS-33).
- `check_crawlers.py` OK proves extraction works on a 2-URL sample; it says nothing about whether a source has ever been crawled — six `HEALTHY` sources had zero `sitemaps` rows on 2026-09-20. Check row counts.
- `process_event` catches `BaseException` and logs at INFO — a failed run looks like a quiet one. Read `crawl_log` (`status`, `error_msg`).
- "Narrow to the one finance leaf" was done on a false premise twice (INEWS had four finance leaves, LIPUTAN6 a disjoint `saham`). List every leaf, decide each.
- Pass-through rate is not recall. On a section that is finance by construction the pass rate *is* the recall, and it was 45–70%. Read the rejects.
- A dry run through the real crawler + real filter with nothing saved (the VIVA audit shape: build `SitemapDTO`s, `batch_crawling_details`, score with the service's own `check_text`) answers "what would a real run do" in 30 s and costs no production rows. Use it before any first real run on a big untested backlog.
- Measuring a filter change on the corpus the previous filter produced cannot see what the previous filter rejected. Always include rejects in the sample.
