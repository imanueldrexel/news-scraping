## Risk list — read this first

**1. Nothing here has touched the live indexes.** The first real use is the 07:00 run: `load_index` taking the save lock over 60 MB + 140 MB, generation tracking across ~28 flushes, the per-source SYS-54 discard. In that run's log, check:
- there is no `StaleIndexError`, since the run should never be refused, because the lock keeps others out;
- flush timings look like 2026-09-26 19:00's;
- `NEWS_L1.lock`/`NEWS_L2.lock` exist in the repo root afterwards (harmless, the OS holds nothing);
- the store check is still all zero.

**2. Untracked indexes are now refused, not saved.** Any code that loads with `FAISS.load_local` and then saves through the chokepoint raises `StaleIndexError("... was not loaded ... through index_generation.load_index")`. I converted `repair_store_consistency` and `requeue_cascaded_articles`; every other writer goes through `ChunkFAISSDatasource`. The dead `faiss_news_data_source.py` (legacy `VECTOR_DB_NAME`, Ollama era, used only by a top-level legacy test) calls `save_local` directly and is not guarded. It is not a NEWS_L1/L2 writer. Confirm nothing else reaches the live indexes that way.

**3. A foreign writer now waits for the save lock before it is refused.** Moving the run-lock check inside the save lock closed a race: a manual save could pass the check just before a run took the lock, then swap in after the worker loaded. The cost is that a foreign writer arriving mid-flush waits for the flush (seconds) before its `RunLockHeld`. After `SAVE_LOCK_TIMEOUT_S = 600` it gets `filelock.Timeout`, not `StaleIndexError`.

**4. `process_event` now raises `RunLockHeld` for `full_text`/`all` during a scheduled run.** A manual crawl that used to run for hours and then be refused at its flush now exits at once, non-zero. `task=sitemap` still runs. Intended, but a behaviour change for the operator.

**5. A failed flush of any kind now drops the block's pending ids.** On a disk-full `OSError` the vectors stay dirty in memory and are saved by the next flush, but their rows stay NULL until that source's next block re-finds them by key. That costs a one-block delay, not data. Before, the ids were assigned by whichever source flushed next. That was correct only because the vectors were still dirty, and SYS-53's reload made it wrong.

**6. SYS-54's discard scans both docstores once per source**, so duplicates are caught too. That is O(docs), a few hundred thousand, and should cost under a second per source, but it is unmeasured on the live index. `run_failures` are passed as candidates even below the fetch cap; the terminal SQL is what filters them. `rejected_filter` rows that **have** an article (the old soft corpus, SYS-48) are deliberately untouched.

**7. OPS-31 edge rules.**
- `psutil.AccessDenied` on the lock's pid counts as "not the owner" (stale), because the scheduled crawl runs as this account.
- A lock whose `started_at` or `create_time` cannot be parsed counts as held; the message says how to clear it.
- Creation-time slack is 1 s.

**8. The generation is file identity, not content.** Copying back a byte-identical generation with `copy2` (same mtime, same size, in-place file id) is correctly *not* a change. My first "restore" test assumed otherwise and was wrong. A restore of any *older* backup is a change.

## Traps worth more than the tickets

**Guard the other side's lock under your own lock.** A check and an action in separate steps race whenever the other party takes a different lock first. Put the run-lock check inside the save lock, because the worker's load takes the save lock.

**State on a long-lived object must be dropped on the failure path, not only consumed on success.** The scheduled worker keeps one repository for every source.

**Turn a repro into the script its unit test runs.** QA's repro and the regression test are now one piece of code (`repro_stale_index_overwrite.py` ↔ `TestTwoSeparateProcesses`).

**The mutation runner owns the working tree while it runs.** Nothing may import repo code from it, and no code may be edited in it, because an unrelated edit contaminates kill/survive. The SYS-53 repro was verified from a `git archive` snapshot meanwhile.
