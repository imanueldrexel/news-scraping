## Risk list — read this first

**1. DBT-10 changed the crash contract, and it has not been exercised by a real kill.** Inside `deferred_embeddings` the vectors stay in memory until one flush at the end of the source, and chunk rows are written with `embedding_id` **NULL** until that flush succeeds. A kill (OPS-22 kills on timeout, by design) leaves NULL rows, and the source's **next** article crawl re-embeds them before it starts. Nothing else does, because those sitemaps have articles and never re-enter the queue. Proven with real FAISS + fake embeddings (kill inside the block, kill between flush and id assignment, failed flush, exception in the body) and by two real clean runs. **Not proven:** a real OPS-22 kill mid-crawl followed by a real next run. The cheapest check after the first days of schedule: `SELECT count(*) FROM chunks WHERE embedding_id IS NULL` must be 0 between runs, and `check_store_consistency.py` must show `chunks sitemap_ids not in FAISS` = 0.

**2. OPS-04's first `--apply` was wrong, and was fixed forward.** It deleted 15,916 vectors of 2,918 terminal VIVA sitemaps but not their 15,916 chunk rows (June SYS-08 debris had both), so `chunks_not_in_faiss` went 0 → 2,918. The checker caught it at once; the plan now removes both halves together and a test pins "no deleted vector stays referenced by a surviving chunk row". Both backups: `backups/faiss_20260925T182149Z/` (before the first apply) and `backups/faiss_20260925T182305Z/` (before the second, plus `orphan_chunk_rows.json`). **Re-verify the end state yourself**, not from my comment.

**3. The schedule went live with VIVA and a much larger fleet than it was sized on.** 28 sources; VIVA's queue is 31,831 rows (newest-first from 2024-01-18), DETIK 9,739, MEDIAINDONESIA ~6,300 net of denied. Per-source cap is still 1,000/run, per-source timeout 900 s, run budget 3 h 30. Unmeasured: whether a morning run fits the budget; how often a source is killed (each kill costs a ~2 min model reload). Read the first runs' Telegram lines and `crawl_log` for `killed by run_scheduled_crawl` and any `run budget … not started` skip.

**4. The per-source soft leaves are judgement calls from 3 titles each.** DETIK 59, KOMPAS 11, VIVA 11. Rule applied: deny only when all 3 titles are soft; a mixed leaf stays for the probe; an empty leaf is not decided by name. Every leaf's titles are in the EXPERIMENTS entries. Re-sample any you doubt with `scripts/experiments/sample_branch_titles.py --website X --all-kept`. Owner-decided drops you may question but should not reverse: KONTAN `english` (it is the Reuters "GLOBAL MARKETS" wire) and WARTAEKONOMI `travel`.

**5. `category_gate` is now source-aware; the AST guard covers `newscrawler/` and top-level `scripts/` only.** `scripts/experiments/` is exempt on purpose (several score text-only by design). A new production call site that forgets the source silently disagrees with the live filter on exactly the per-source leaves.

**6. INEWS's own body extractor returns 0 characters** on live pages (SRC-19 #99, pre-existing, open). The 450 INEWS articles saved tonight came through the trafilatura fallback.

## Traps worth more than the tickets

**`page_loader.get_url_with_reason` returns the response for any HTTP status, a 404 included.** My first SRC-29 probe used it and reported 342/342 "alive"; truly 333/342 were 404. Probe liveness with `get_soup_with_reason`, the call the crawl makes.

**A deletion that removes one store's half of a pair creates the divergence it exists to fix** (OPS-04, risk 2). Check every referrer of a key before deleting it, and run the checker straight after any write.

**A collision check against stored rows cannot see a branch that was never stored.** DETIK's `sehat` was collision-free against every stored category, and KONTAN lists an empty `sehat` branch of its own. Only the live `probe_branch_category_mismatch.py` saw it, which is why the leaves became source-scoped.

**A source can have more than one sitemap index** (KOMPAS has three). Any tool that does `_get_branches(get_soup(website_url))` sees only the primary; use `crawler.list_branches()`.

**A kill signal sent from inside a container does not test its restart policy** (PID 1 ignores it). `docker desktop restart` does.
