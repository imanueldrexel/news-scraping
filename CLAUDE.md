## What this is

NewsAggregator: crawls ~30 Indonesian news portals (sitemap-driven; KAPANLAGI and BATAMPOS retired 2026-09-20, no usable finance content; GRIDID retired 2026-09-25, SRC-37/SRC-52: every branch a lifestyle/gossip/hobby magazine, 0 articles ever), keeps only finance/economy articles (semantic filter) — **scope is changing to "news-worthy" (hard news in; recipes/prayers/gossip/listicles/sports out) per the 2026-09-20 owner decision: SYS-36/37 (#120/#121) replace the filter, SRC-34 (#124) widens the crawlers, SYS-39/40/41 (#125–#127) scale extraction/newsletter/vector store; SYS-37 landed 2026-09-22: the filter is the probe in `newscrawler/core/models/` (see Architecture)** — chunks + embeds them into local FAISS indexes, stores everything in PostgreSQL, and builds three products on top: an entity knowledge base (Gemini extraction), a daily markdown newsletter (topic sections, clustered within each), and a RAG search web UI (FastAPI). See `PRD.md` for the design/product spec and `OPERATIONS.md` for the runbook (env-var table, SQL health queries, schedule).

**Two codebases live here; only one is active.**
- `newscrawler/` — the real, actively developed pipeline (Postgres + FAISS + sentence-transformers + Gemini). All work goes here.
- `services/`, `shared/`, `docker-compose.yml`, `MICROSERVICES_README.md`, `.env.example`, `check_dupe.py`, `scripts/init_chromadb.py|init_neo4j.cypher|pull_models.sh` — an **abandoned** Jan-2026 microservices prototype (Redis Streams / Neo4j / ChromaDB / Ollama), kept in the repo for reference only. Do not extend it and do not treat `.env.example` as the config reference for `newscrawler` — `OPERATIONS.md` has the real variable table.
- `model_inference/` — standalone IndoBERT+LSTM category classifier (13 classes) from the modelling notebooks; loads weights from hard-coded local paths and is not wired into the pipeline.

Always work in this main repo root, never under `.claude/worktrees/` — the app is run from here.

## Workflow: issue first, then code

Every new bug and every new or changed requirement gets a GitHub issue **before** any code is written — no matter how small the fix, and regardless of whether a human or Claude found it. Then reference the issue in the commit with `Refs #N`. Do not use `Fixes #N`: it would close the ticket on merge, and only QA closes tickets (next section).

## Workflow: dev does the ticket, QA closes it (owner decision 2026-09-29)

Two roles. Every session works in one of them; a session that is asked to "work the QA list" or fix tickets is **dev**, a session that audits or verifies is **QA**.

- **Dev** implements a ticket, then posts the Done-when evidence on it as a comment, adds the label `status: ready-for-qa`, and leaves it **open**. Dev never closes a ticket. Commit footers use `Refs #N` only. Dev still files an issue before coding a bug it finds while implementing (issue-first above), but it does not file tickets from testing or auditing.
- **QA** verifies each `status: ready-for-qa` ticket independently: suites, its own mutants, live or read-only checks, and the scheduled-run evidence where the Done-when needs it. Then QA either **closes it** (removing the label, with a comment saying what was checked) or **sends it back**: remove the label and comment what fails. A separate defect goes in a new ticket. QA **files every new ticket that comes from testing**: audits, mutation runs, run watching.
- A ticket whose Done-when needs N scheduled runs stays `ready-for-qa` until QA has seen them.

## Workflow: log every experiment

Whenever you probe a site, test a hypothesis, try an approach that might not work, benchmark, or compare options, add an entry to **`EXPERIMENTS.md`** in the same session — succeeded, failed, or inconclusive. Failed experiments are the most valuable entries.

- Read the **"Traps & settled questions"** section at the top of `EXPERIMENTS.md` before starting any scraper or pipeline investigation; it lists what has already been ruled out.
- Entry format is at the top of the file: date + title · Question/hypothesis · Method (exact command or `scripts/experiments/` path) · Result (numbers, exact errors) · Conclusion / do-not-repeat · Links (issue #, commit).
- Reusable diagnostics go in `scripts/experiments/` (e.g. `probe_sitemap_ua.py`); throwaway repro code is inlined in the entry, not left in a scratchpad.
- When a conclusion changes the default approach, add a one-liner to "Traps & settled questions" pointing at the entry.
- Commit the log entry with the related work (`Refs #N`).

## Architecture

Layered (clean-architecture style). Dependencies point inward: `application/api` → `domain/services` → `domain/repositories` (abstract) ← `infrastructure/repositories` (impl) → `infrastructure/datasource` (SQLAlchemy, FAISS, scrapers).

### Wiring & dispatch

`lambda_handler.process_event(event, ctx)` is the single entry point for every task. `init_crawler()` builds `SQLAlchemyClient → DataFlowRepositoryImpl → CrawlerServiceImpl(chunker) → CrawlerAPI`; `CrawlerAPI.crawl_website` switches on `event["task"]`. Note `process_event` catches `BaseException` and logs it at INFO — failures are effectively silent at the top level; check the `crawl_log` table (`status`, `error_msg`) instead.

`DataFlowRepositoryImpl` is the composition root for infrastructure: it owns `NewsDataSource` (sitemaps + articles SQL), `ChunkFAISSDatasource`, `SQLAlchemyChunkDataSource`, `KnowledgeExtractor`, and `NewsletterGenerator`. Constructing it loads the sentence-transformers model and both FAISS indexes, so it is slow (~10s+) — the web app lazily builds these singletons on first request.

### The crawl pipeline (`task=all`) — `CrawlerServiceImpl`

1. **Sitemap crawl** (`crawl_sitemaps`): `Crawler.get_news_in_bulk()` fetches the site's sitemap index, `_get_branches(soup)` picks the news sub-sitemaps, `_scrape()` reads each `<url>` entry (`loc`, `news:title`, `news:publication_date`, `news:keywords`) into dicts → `SitemapDTO`s → `save_sitemap_data`. Dedup key is the `link` alone (SYS-29 — enforced by `sitemaps_link_uq`; it used to be `(link, posted_at)`, which re-inserted a stored URL whenever the derived date moved), and `posted_at` is stored as an **int `yyyymmdd`**, not a timestamp. `save_sitemaps` returns DTOs with `sitemap_id` populated (DTOs are frozen pydantic dataclasses, so it uses `dataclasses.replace`) and the service passes those directly into step 2. An index that does not load (or a source whose every branch fails) raises `SitemapIndexUnavailable` and the run is `failed` with the reason (OPS-35); a partial branch failure is a note on the completed row. A branch that can never load is kept out of that "did not load" list (SRC-58): a host DNS says does not exist (PIKIRANRAKYAT's 62 regional subdomains) or a `<loc>` with no host is not fetched at all ("skipped"), and a 404/410 or a redirect to a malformed URL is "gone"; both are counted apart in the note, and a source whose every branch is dead still fails. The DNS skip is trusted only while the index's own host resolves.
   **Fetching (SYS-66/SYS-70):** every request goes through `RequestsPageLoader`: 3 retries with exponential backoff, a dead host named `NameResolutionError after N retries` (never counted by SRC-55's breaker, which does count 403/429 and refusals), a per-host gate (`HOST_MIN_INTERVAL_S`/`HOST_MAX_CONCURRENCY`, KUMPARAN 1 req/s), `Retry-After` honoured once, and the `NewsAggregatorBot/1.0` UA except `BROWSER_UA_HOSTS` (the three sources that refuse it). Throughput (20 threads) is kept by owner decision; tighten per host from measurements, not fleet-wide.
2. **Article crawl** (`crawl_newsdetails`): per batch, `batch_crawling_details` runs `_get_news_details` in a `ThreadPoolExecutor` (serial only for MEDIAINDONESIA). Text extraction is site-specific `_get_whole_text(soup)` → trafilatura fallback → newspaper3k fallback. Then, in order:
   - `mark_sitemaps_attempted()` stamps `sitemaps.last_crawl_attempt` for every successfully-extracted sitemap so it leaves the queue for the cooldown window. Fetch/extraction failures are collected for the run with their reason (`NewsDetailsBatch.failures`, from the page loader / extractor) and, at the end of the run, `increment_fetch_failures` bumps `sitemaps.fetch_failures` per reason and stamps the cooldown too (SYS-09) — `load_all_sitemaps` stops offering a sitemap at `SITEMAP_MAX_FETCH_FAILURES` (default 3; `scripts/reset_fetch_failures.py` undoes it). A run is source-wide only when at least `SITEMAP_SOURCE_FAILURE_RATIO` (default 1.0 = all) **and** at least `SITEMAP_SOURCE_FAILURE_MIN` (default 20) of its sitemaps failed (OPS-16). Then per-URL reasons (404/410/soft-404) are still counted, the source-level ones (403, 5xx, connection) are spared but cooldown-stamped, and the verdict is logged at ERROR and persisted in `crawl_log.error_msg`. Below the floor every failure counts individually, except a transient one (SYS-62: `<Error> after N retries`, 403/408/429/5xx), which is a strike only when the row's previous `last_fetch_error` was transient too; a first one stores its reason and the cooldown stamp (`record_fetch_error`), so one burst no longer strikes working URLs. OPERATIONS.md "Check dead-link accumulation" has the details and the residual risk.
   - `SemanticImportanceFilter.classify_batch(texts, categories)` (`classify`/`is_important` are wrappers) is **the one news-worthy decision** (SYS-37, live 2026-09-22). Category gate first: `category_gate()` in `core/importance_filter.py` returns `deny` for a soft vertical (since SYS-50 a denied row is settled `rejected_filter` **before it is fetched** by `_split_denied_by_category`, and `attempted` counts only fetched rows; the post-fetch check is a backstop), `allow` for a news desk in `NEWS_CATEGORIES`, `None` for a mixed bucket (`news`, `berita`, regional subdomains); **`allow` and `None` are both decided by the probe** (SYS-45: a news desk means the score cannot reject, the probe can). The probe is `core/importance_probe.py`: two logistic-regression heads (P(soft) gate; 13-class topic) over the `intfloat/multilingual-e5-large` embedding of `build_check_text(title, body)` (title + body[:500], 200-word cut), loaded from the committed artifact `core/models/importance_probe.npz` + `.json` (encoder name, τ=0.39, gold sha256, metrics) — a missing/mismatched artifact raises `ProbeArtifactError` at service start. Retrain only with `scripts/train_importance_probe.py` (it refuses to write below the SYS-37 gates − the owner's 0.02 tolerance); `SOFT_THRESHOLD` is the only runtime knob; `INTERESTS`/threshold/margin no longer exist. The decision carries `topic`/`topic_confidence` onto `articles.topic`. Every backfill/re-queue script calls `classify_batch`, never a local copy (a test forbids one). An article with no extracted body is `empty_extraction` before the filter runs. Articles the filter rejects are **never saved** (`rejected_filter`, terminal); this is by design. The run logs per-gate counts, the probe's keep rate per news category, the uncertain-band share (P(soft) in [0.35, 0.65]), and a WARNING the first time a source saves under a category it never saved under before (SYS-34).
   - `HierarchicalChunker.chunk()` → L1 chunk (first two paragraphs, for clustering) + L2 chunks: windows of at most 80 whitespace words with 20 overlap, merging short paragraphs from 40 (SYS-109, ADR-008: MiniLM embeds only 128 tokens, ~83 Indonesian words; chunks were up to 450 words and mostly unseen). A short last paragraph merges backward (SYS-105: a trailing "(jon)" chunk was a search hub). `scripts/rechunk_stale_chunks.py` re-chunks stored articles L2-only (L1 and mentions untouched).
   - `save_chunk_data`: embeds into the `NEWS_L1/` and `NEWS_L2/` FAISS directories (LangChain FAISS + HuggingFace `paraphrase-multilingual-MiniLM-L12-v2`, normalized). FAISS dedups by `sitemap_id` found in the docstore; already-embedded chunks come back with `embedding_id=None` and are *not* re-inserted into the SQL `chunks` table, but their `sitemap_id`s *are* still returned so the article row gets saved. Every FAISS save goes through `ChunkFAISSDatasource._atomic_save_local`, which refuses while the scheduled crawl holds `.scheduled_crawl.lock` (OPS-26: its worker keeps both indexes in memory for the whole run and would overwrite the save). A script that writes FAISS must also call `newscrawler.tools.run_lock.refused_by_run_lock(logger)` on its write path, before any fetch or SQL, and exit 2; `tests/unit/test_run_lock.py` fails for a script that doesn't (DBT-43: it finds writers by what they use, `ChunkFAISSDatasource`/`DataFlowRepositoryImpl`/`load_index`/`init_crawler`/`process_event`, and runs each one's write path under a held lock). The lock guards "now"; SYS-53's generation check guards "since I loaded": a save is refused (`StaleIndexError`) when the index on disk changed after this process read it, so a writer must load through `index_generation.load_index` (or `ChunkFAISSDatasource`), never `FAISS.load_local`. A save commits the pair as a whole (SYS-56: stage in `NEWS_L*.tmp`, rename to `NEWS_L*.commit`, roll forward; `load_index` finishes an interrupted one and refuses a pair whose `index.faiss` and `index.pkl` disagree with `CorruptIndexError`), because `FAISS.delete` renumbers positions and a torn pair would silently return the wrong documents. From the commit point on, the writer tracks the generation it committed, whoever rolls it forward (SYS-60). The pair also carries `encoder.json` (the MiniLM revision), and the probe sidecar carries `embedding_revision`; building against another revision of either encoder raises (SYS-61, OPERATIONS.md "pick up a newer revision"). When the crawl settles a sitemap as terminal it removes that sitemap's vectors and chunk rows in the same block (SYS-54); the sitemaps come from the store (this source's terminal sitemaps that still have chunk rows), swept when the block opens and after the last batch, so a killed run is cleaned up by the next (SYS-57).
   - `save_newsdetails_data` → `articles` row (`meta_data.posted_at` also converted to int `yyyymmdd`).

The article-crawl queue (`load_all_sitemaps`) = sitemaps with no `articles` row AND (`last_crawl_attempt` IS NULL OR older than `SITEMAP_RECRAWL_COOLDOWN_DAYS`), newest first, limited to 1000. Both the cooldown stamp and the "return all sitemap_ids from FAISS" behaviour were bug fixes for a "thousands of sitemaps, no articles" gap — don't regress them (covered by `tests/unit/test_mark_attempted_wiring.py` and `test_save_chunk_data.py`).

### Downstream phases

- **Knowledge extraction** (`core/knowledge_extractor.py`, provider in `core/extraction_provider.py`, ADR-003 / SYS-39): an `ExtractionProvider` (`KNOWLEDGE_LLM_PROVIDER`: `openai` = SumoPod DeepSeek, `gemini` = the default until the owner confirms the switch on #136) extracts persons/orgs/locations/event_type per article, finance topics first, until the queue is empty; a run stops on the provider's peak window (`core/peak_hours.py`), the day's dollar budget (`api_usage_log.cost_usd`, `KNOWLEDGE_DAILY_COST_LIMIT_USD`), a per-day quota, or 5 failures in a row, and its `crawl_log` note carries tokens, cost and the stop reason. The OPS-09 line stays: `ProviderTransientError` (no response) never counts against an article. `EntityNormalizer` + `entity_aliases` map names to canonical entities, results go to `entities` / `entity_mentions`, and `articles.knowledge_extracted` is flipped. Calls, tokens and dollars are tracked per model and day in `api_usage_log`. It warns and does nothing when the chosen provider has no key.
- **Newsletter** (`core/newsletter_generator.py`): the date's articles sectioned by `articles.topic` in `filter_rubric` order (finance topics first), average-linkage clustering of L1 embeddings **within** each topic (SYS-40 replaced DBSCAN, which chained), at most `NEWSLETTER_MAX_CLUSTERS_PER_TOPIC` clusters shown per section (ranked by size × sources, the rest counted) → summaries → `digests/YYYY-MM-DD.md` + `newsletter_digests` row whose `categories` is the per-topic composition (SYS-40). It embeds with the FAISS store's MiniLM (DBT-02). Since tracker #244 (2026-10-05) that digest is the **archive**; the delivered product is the 5-minute edition `digests/YYYY-MM-DD-ringkas.md`. Each story's summary is JSON from `core/story_summary.py` (SYS-82), refused when it breaks a word limit, carries a number its `terkait` articles lack (compared by value, SYS-87), or keeps an article `terkait` that names none of the summary's subjects (SYS-80); the headline/links/portal count come only from the `terkait` articles. `core/story_words.py` is the one definition of a story's content words and names (titles, months, number units and digit tokens are neither), read by that subject check and the edition's echo guard (SYS-86). `core/newsletter_edition.py` (SYS-83) picks the top stories with one editor call checked against the owner's quotas (deterministic fallback), and the 1,200-word budget trims Sekilas only. Every reader-facing string, date and outlet name lives in `core/newsletter_copy.py` (SYS-84/SYS-81): never `strftime("%B")`, never a source enum in the reader's text, no telemetry in the document. `core/newsletter_pdf.py` renders the A4 archive and the phone edition (OPS-41/42); the 12:00 job sends a 60-second message plus the edition PDF (OPS-43).
- **RAG web UI "Tanya Berita"** (`web/`, tracker #272, ADR-005): FastAPI + Jinja + htmx (vendored in `static/`). A question takes two requests:
  - `retrieve`: hybrid FAISS L2 + Postgres FTS, merged per article.
    - Headline, portal, date and `articles.topic` come from the DB, not FAISS metadata. A hit without an article row is dropped.
    - Topic / portal / date filters are applied in the FTS SQL; the semantic search over-fetches `RAG_FILTERED_K` and filters after.
    - The keyword half (`web/keywords.py`, SYS-103, ADR-006) matches the question's rare words (anchors) and scores IDF-weighted coverage; df from `pg_stats` + exact counts for rare words. A keyword hit survives the semantic floor at `RAG_MIN_KEYWORD_COVERAGE`.
    - ADR-007: a matched paragraph under 15 words is skipped. An article one retriever found is scored on the other signal too (its stored NEWS_L2 vector's cosine, or its coverage), so the weighted sum compares like with like. `semantic_score` is the cosine, `1 - d/2` of FAISS's squared distance (SYS-110).
    - A recency cue (`keywords.recency_cue`: "hari ini" 1 day/0.3, "pekan ini" 3/0.2, "terbaru" 7/0.1) weighs recency for articles relevant by meaning only. A follow-up is retrieved with the session's last two questions, answered or not (SYS-104).
    - Results are re-ranked and cut at the floor.
    - The source cards render at once.
  - `answer`: through the shared `Summarizer` (`RAG_LLM_PROVIDER`, DeepSeek by owner decision).
    - It returns a state (`ok`/`unavailable`/`failed`/`no_hits`), never an error text.
    - Usage is counted under `web:<model>` with tokens and dollars, capped by `RAG_DAILY_COST_LIMIT_USD`.
    - The model's text is parsed into text/`[n]` segments (`web/answer.py`). A citation links only to a card that exists. The answer's numbers are checked against the cited articles.

  Rules:
  - Templates never use `| safe`.
  - Every reader string lives in `core/web_copy.py`; tests enforce both.
  - One uvicorn worker: sessions and pending turns are in memory.

### Site crawlers

Each outlet is a `Crawler` subclass in `infrastructure/datasource/scrapers/<site>/`. Registering a new one requires touching **four** places: `WebsiteName` enum, `URL` enum (`domain/entities/extraction/`), `CRAWLER_DICT` (`core/crawler_dict_list.py`) and `WEB_URL_DICT` (`core/crawler_url_list.py`). `CRAWLER_DICT` instantiates every crawler at import time. A subclass sets `website_name`/`website_url` and implements `_get_branches`, `_get_reporter_from_text` and -- only when `PRIMARY_EXTRACTOR = "site"` (the default) -- `_get_whole_text`; a source whose selector measured worse than trafilatura or dead declares `PRIMARY_EXTRACTOR = "trafilatura"` and has no selector (DBT-05, 2026-09-29: 13 sources; `tests/unit/test_primary_extractor.py` holds the list, and `check_crawlers.py`'s FALLBACK means "the declared extractor failed"); `out_of_scope_reason(link)` drops a listed URL before it is stored, for what a branch name cannot say (SRC-60: KUMPARAN's reader posts share the news branches); override `_scrape`/`_get_link` only when the sitemap deviates from the standard Google-news format. The base `_get_link` appends `?page=all` to every URL except JPNN. Body extractors should run paragraph text through `core/utils/utils.py:preprocess_text` and drop "Baca juga"-style boilerplate.

**Scraper scope requirement (SRC-39, #133 — owner decision 2026-09-20; the code does not yet comply, see the child tickets there):** a crawler lists **every section its outlet publishes that carries hard news** — national, political, legal/crime, regional, international, economy/business/markets, science/tech developments, health/education policy — and **drops, by branch name, the soft verticals**: sport, entertainment/celebrity, lifestyle/fashion/beauty, food/recipes, travel, religion guides, hobby-automotive, games, horoscopes, fiction, English editions, **video/photo galleries and calendar archives** (SRC-45 — `gallery`/`video`/`foto` by name plus `Crawler.is_archive_branch`, which drops any `YYYY-MM` partition key; decided by measuring the extracted body, so a section merely *named* after a medium that publishes real articles is a `SOFT_BRANCH_EXCEPTIONS` entry with its char count — IDXCHANNEL `foto`, BERITASATU `multimedia`, VIVA `viva-visual`), and **opinion/analysis/editorial columns** (`opini`, `editorials`, `kolom-pakar`, `surat-pembaca`, `scope`, `tajuk` — SYS-49, owner decision 2026-09-23: an op-ed argues about an event, it is not one). Decide per leaf from a 3-title sample and record it on the source's ticket — never from the leaf's name alone (WARTAEKONOMI `otomotif`/`kesehatan`/`transportasi` are business coverage). The drop is enforced once, in the base `Crawler` -- `SOFT_BRANCH_WORDS` + `is_soft_branch`/`drop_soft_branches`, applied in `get_news_in_bulk` (SRC-35, landed 2026-09-22). Fleet as of 2026-09-23, end of day: **1,092 branches listed → 327 dropped as soft + 140 dropped as archive → 625 crawled**; since SRC-33 no live branch is keyed by URL, and since SRC-53 (2026-09-26) no stored `sitemaps.category` is a URL either (`check_store_consistency.py`'s `sitemaps_url_category`, baseline 0). Per-crawler `SOFT_BRANCH_EXCEPTIONS` for names a 3-title sample proved are business coverage -- not per subclass -- and only for a name the category gate does NOT also deny for that source (SRC-52: KONTAN `english` and WARTAEKONOMI `travel` were exceptions whose rows were then all rejected at category level; removed 2026-09-25, and a test now fails on any such exception). The reverse, a soft leaf no vocabulary word reaches (DETIK's `f1`, `relationship` = horoscopes), goes in `importance_filter.SOURCE_SOFT_LEAVES[<source>]` and the crawler's `SOFT_BRANCH_DENY` points at that same set: it is denied at branch level and, **for that source only**, at category level, which is why `category_gate`/`classify_batch` take the source and every production call site must pass it (SRC-50, 2026-09-25: DETIK 173 → 114 crawled). Before adding one, run `sample_branch_titles.py --website X --all-kept` and `probe_branch_category_mismatch.py`. A branch is never keyed by its URL: a `<loc>` the subclass cannot name is skipped (`re.match` + skip, never `re.sub`, which returns the input unchanged on no match). Two tests enforce this: `TestFleetNeverKeysABranchByItsUrl` offline, and `probe_branch_scope.py --fail-on-url-keys` live. Watch the other `re.sub` failure mode too -- a pattern that captures too little makes several sections share one dict key and silently drops all but the last (SRC-44: OKEZONE lost 38 of 72 `<loc>`). The semantic filter decides news-worthy vs soft *within* a listed section; it is not a substitute for listing the right sections. A source with no hard-news section is retired, not narrowed. **Do not narrow a crawler to a finance leaf** — the SRC-05..28 "keep bisnis only" commits are the old policy, not the current one. `scripts/experiments/probe_branch_scope.py` prints every registered crawler's live branch set with soft/finance/URL-key counts; run it before and after any `_get_branches` change.

Many crawlers rot as sites change; as of 2026-06-02 only 13/32 were healthy. Use `scripts/check_crawlers.py --website <NAME>` to verify a scraper before and after changing it.

### Database schema

Tables: `sitemaps`, `articles`, `chunks`, `entities`, `entity_aliases`, `entity_mentions`, `api_usage_log`, `newsletter_digests`, `crawl_log`. The schema is owned by the SQL files in `scripts/migrate_*.sql` — `Base.metadata.create_all` is never called. The SQLAlchemy models in `infrastructure/datasource/dataflow/write/sqlalchemy/table.py` and `knowledge_table.py` must be kept in sync by hand; several past outages were `DatatypeMismatch` errors from drift between the two (e.g. `is_embedded` int vs bool). Most reads are raw `text()` SQL built from `Table.column.name`, not ORM queries.
